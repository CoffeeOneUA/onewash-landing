# One Wash — Landing Page + запис онлайн

Промо-сайт автомийки **One Wash** (Тернопіль, вул. Протасевича 11А) з калькулятором запису, реальним прайсом і онлайн-оплатою через WayForPay.

## Структура

- `index.html` — готовий до деплою статичний файл (шрифти, лого, фото вбудовані як `data:` URI).
- `template.html` / `build.js` — вихідники для перезбірки `index.html` (плейсхолдери `__..._B64__`).
- `api/` — серверні функції Vercel (Node, без зовнішніх залежностей — лише `fetch` до Supabase REST і WayForPay):
  - `available-slots.js` — GET, повертає вільний час на дату з урахуванням `location_working_hours`, `staff_schedule`, `staff_schedule_dates`, зайнятості майстрів і зайнятості боксів (`wash_boxes`, з урахуванням `is_active`) з `bookings`.
  - `create-payment.js` — POST, рахує ціну **на сервері** (не довіряє даним з браузера), перевіряє слот ще раз, створює запис у `payment_links`, повертає підписаний запит на оплату WayForPay.
  - `wayforpay-callback.js` — webhook (`serviceUrl`), перевіряє підпис WayForPay, після підтвердженої оплати створює/знаходить `clients`, опційно `cars`, створює `bookings` + `booking_extras`, оновлює `payment_links`.
  - `order-status.js` — GET, статус платежу за `order_reference` (для сторінки підтвердження на сайті).

## Змінні середовища (Vercel → Settings → Environment Variables)

| Змінна | Призначення |
|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` | Обхід RLS для запису підтверджених записів (тільки на сервері) |
| `WAYFORPAY_MERCHANT_ACCOUNT` | Логін мерчанта WayForPay |
| `WAYFORPAY_SECRET_KEY` | Секретний ключ підпису WayForPay |
| `WAYFORPAY_DOMAIN` | Домен, прив'язаний до мерчант-акаунту (напр. `onewash-landing.vercel.app`) |
| `SUPABASE_URL` | (опційно) інакше береться дефолтний URL проєкту One Wash |

## Відомі припущення, які варто перевірити перед реальними платежами

1. **`weekday` в `location_working_hours` / `staff_schedule`** — код вважає, що це ISO-конвенція (1=понеділок…7=неділя). Якщо у вас 0=неділя…6=субота, поміняйте `WEEKDAY_ISO` у `api/_lib/availability.js`.
2. **`bookings.status`** — вебхук пише `'confirmed'`. У БД це звичайний `text` без обмежень, але переконайтесь, що адмінка коректно відображає саме цей рядок статусу (не якийсь інший, напр. `'scheduled'`).
3. **Інтеграція WayForPay не тестувалась на реальному акаунті** — обов'язково проведіть тестову транзакцію (тестові картки WayForPay) перед запуском у продакшн.
4. **Гонка при бронюванні слоту** — між натисканням "Сплатити" і підтвердженням оплати слот формально ще не заброньований (тільки `payment_links` зі статусом `pending`), тому теоретично двоє клієнтів можуть обрати один і той самий час (або той самий бокс). Для MVP це прийнятний ризик; за потреби можна додати "м'яке бронювання" слоту на час оплати.
5. **`wash_boxes.is_active`** — якщо міграцію з попереднього кроку (`alter table wash_boxes add column is_active...`) ще не застосовано, код трактує всі бокси як активні (безпечний фолбек). Після додавання стовпця вимкнені в адмінці бокси одразу перестануть пропонуватись і на сайті.
6. **WayForPay-реквізити зараз глобальні (Vercel env vars), а не per-location** — у самій адмінці (`admin/services.html`) вже є окрема таблиця `location_payment_credentials` для реквізитів WayForPay кожної мийки. Сайт цей механізм поки не використовує. Якщо власник змінить реквізити через адмінку, на сайті доведеться оновлювати Vercel env vars вручну. Можна переробити `create-payment.js`, щоб він читав реквізити з `location_payment_credentials` замість env vars — скажіть, якщо це потрібно.

## Деплой

Vercel підхоплює `/api/*.js` як serverless-функції автоматично, окремого налаштування білду не потрібно. Framework Preset: **Other**, Build Command — порожній, Output Directory — `.`.
